# Synapse v2.1.21: "a query string is part of the path"

Patch release fixing the last step of the MCP OAuth flow in a browser. No schema
migrations, no new endpoints, no new configuration keys.

## Fixed

### The service worker served the SPA instead of the OAuth consent page [F17]

Clicking "Connect" on the claude.ai custom connector opened
`/authorize?response_type=code&...` and showed the SPA's setup wizard, not the backend's
"Authorize MCP access" page. A hard reload (which bypasses the service worker) showed the
right page, and curl always did.

`/authorize` was already in the Workbox `navigateFallbackDenylist`, but Workbox's
`NavigationRoute` tests the denylist against `url.pathname + url.search`, and every pattern
ended in `(\/|$)`. Any navigation with a query string escaped the denylist and got the
cached `index.html`. The patterns are now built by `src/pwa/navigateDenylist.ts` with a
`(\/|\?|$)` boundary and an escaped prefix (the dot in `/.well-known`), and covered by
`src/tests/navigateDenylist.test.ts`. The same fix applies to every API prefix the SW
denies.

Browsers that already installed the old service worker pick up the new one on their next
visit (`registerType: autoUpdate`).

### A wrong token on the consent page looked like nothing happened

`POST /authorize` with an invalid token did answer 401 with an error, but as one small red
line above an identical form. It is now a bordered `role="alert"` box ("Invalid token:
access was not granted...") and the tab title starts with "Error:".
