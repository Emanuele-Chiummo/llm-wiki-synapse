# Synapse v2.1.18: "the scheme the tunnel saw"

Patch release fixing the OAuth discovery metadata of the remote MCP surface behind a TLS
terminating proxy. No schema migrations, no new endpoints, no new configuration keys.

## Fixed

### OAuth issuer advertised `http://` behind the Cloudflare Tunnel [F17]

`_issuer()` in `backend/app/mcp/oauth.py` built the issuer from `request.url.scheme`. Behind
the Cloudflare Tunnel uvicorn receives plain http, so both
`/.well-known/oauth-authorization-server` and `/.well-known/oauth-protected-resource`
advertised `http://<host>`. Strict clients such as `mcp-remote` compare the issuer with the
URL they fetched it from and stopped with `IssuerMismatchError`.

The issuer now honours `X-Forwarded-Proto` (first hop, `http` or `https` only), the same rule
`SecurityHeadersMiddleware` already applies to HSTS. Without the header, or with any other
value, the transport scheme is kept. No domain is hardcoded (I6).

uvicorn `--proxy-headers` was not used: it would also rewrite `scope["client"]` from
`X-Forwarded-For` and bypass the trusted-proxy model in `app.client_ip` (ADR-0033 §2.3).

Regression tests in `backend/tests/test_mcp_oauth.py` cover the proxied and the
unproxied/junk-header cases.
